# 보고서 구조 — 대가의 방식 (KB)

보고서를 잘 쓰는 사람은 ‘무엇을 쓸까’보다 ‘어떤 순서로 보여줄까’를 먼저 정한다.
이 파일이 첨부되면 아래 구조 원칙으로 초안을 짠다.

## 1. 결론부터 (피라미드 구조)
- 첫 줄 = 읽는 사람이 꼭 알아야 할 결론 한 문장
- 그 아래 = 결론을 받치는 이유 3개
- 그 아래 = 각 이유의 근거(숫자 · 사례)
- 읽는 사람이 첫 문단만 보고 멈춰도 결정을 내릴 수 있어야 한다

## 2. 이야기 순서 (상황 → 문제 → 질문 → 답)
1. 상황 : 모두가 아는 사실 (예 : 문의가 매달 늘고 있다)
2. 문제 : 그래서 생긴 곤란 (예 : 첫 응답이 6시간 걸린다)
3. 질문 : 그럼 무엇을 해야 하나
4. 답 : 우리의 제안 (= 보고서의 결론)

## 3. 나누는 법 (빠짐없이, 겹치지 않게)
- 개선안 · 원인 · 대상을 나눌 때 서로 겹치지 않고, 합치면 전체가 되게
- 좋은 예 : 사람 / 절차 / 도구 · 단기 / 중기 / 장기 · 고객 / 내부
- 나쁜 예 : “속도 개선 / 응대 개선 / 효율화” (서로 겹침)

## 4. 3의 법칙
- 이유 · 개선안 · 기대 효과는 3개로 맞춘다 (2개는 빈약, 5개는 안 읽힘)
- 4개 이상이면 묶어서 3개로 만든다

## 5. 읽는 사람 기준 점검
- 팀장 : 결론 · 비용 · 일정이 첫 화면에 있나
- 임원 : 한 줄 요약과 숫자 하나로 판단 가능한가
- 실무자 : 누가 · 언제 · 무엇을 하는지 보이나

## 6. 하지 말 것
- 배경 설명으로 시작하기 (결론이 3쪽에 나옴)
- 자료를 모은 순서대로 쓰기
- 근거 없는 결론, 결론 없는 근거
